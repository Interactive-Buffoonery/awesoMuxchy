# Electron behavior handoff for native GTK

This is a regression backlog, not an implementation specification or product copy source. The macOS baseline and `shared/resources/text-baseline.json` remain authoritative for shipped behavior and wording. The Electron prototype supplies Linux failure cases and test fixtures worth retaining while the active Swift/GTK/Ghostty track replaces its runtime.

Evidence is pinned to Electron commit `ee95c6a74910ff8a8b1d01493e8a4c192e3199c1` (MIT; see `LICENSE`). The complete source, tests, screenshots, history, and repository metadata are preserved in the [local legacy Electron archive](../reference/legacy-electron/README.md). Restore its bundle as described there, then use `git show ee95c6a:path` for every `E:` path below. `E:` always means a path at that commit in the Electron repository; `G:` means a path in this GTK repository. Paths and acceptance cases here are enough to triage work without the former checkout or GitHub. Do not copy xterm/React/Electron code into GTK. Some Electron policies are intentionally narrower than the macOS product and need reconciliation before implementation.

## P0: process and lifecycle safety

**EL-01 — Owned process teardown with a bounded result.** Electron's `E:src/main/index.ts` (`closeTerminal`, `closeAllTerminals`, `before-quit`, and window `close`) removes a terminal from the live map, suppresses further data callbacks, awaits a bounded signal sequence, then disposes listeners. `E:src/main/terminal-shutdown.ts` and `E:tests/terminal-shutdown.test.ts` cover HUP → TERM → KILL, stopping after exit, signal failure, timeout, and a real Linux PTY. GTK currently calls `requestClose()`, moves the object into `retiringSurfaces`, and polls for `processExited` in `G:swift-gtk/Sources/AwesoMuxApp/main.swift` (`discardPaneRuntime`); the Ghostty wrapper exposes `requestClose` and `processExited` in `G:swift-gtk/Sources/AwesoMuxTerminal/TerminalRuntime.swift`. **Gap:** explicit ownership and final outcome for a stubborn child, callback retirement, app quit, and interrupted shutdown remain unproven. Add a Ghostty appropriate lifecycle result and bounded stress scenario: close a pane running a child that ignores HUP, verify that only that pane's owned session is terminated or a clear failure is reported, no late callback reaches released Swift/GTK state, another busy pane remains usable, and quitting cannot hang indefinitely. Do not mechanically send signals to Ghostty's internal process or copy node-pty timing constants; Ghostty owns its PTY and its documented close contract must drive the design.

**EL-02 — Risk classification is pane scoped and conservative.** `E:src/main/platform/linux-process.ts`, `E:src/main/platform/linux.ts`, `E:src/domain/terminal-interruption.ts`, and `E:tests/linux-process-activity.test.ts` and `E:tests/terminal-interruption.test.ts` demonstrate foreground process group inspection, safe bounded process labels, and confirmation on unknown state. GTK already has a stronger product policy in `G:swift-gtk/Sources/AwesoMuxCore/CloseRiskPolicy.swift`, with Ghostty prompt and foreground PID inputs in `G:swift-gtk/Sources/AwesoMuxApp/main.swift` (`closeRiskInputs`), and real close/reopen coverage in the parity matrix. **Gap:** confirm the same policy across pane close, group close, clear, restart, and whole-app quit, including unreadable `/proc`, exited children, stale agent state, and a process changing state while a sheet is open. Acceptance: each destructive action revalidates its exact target before committing; unknown live state gets a safe default; cancelling leaves all owned processes and durable state intact. Do not port Electron's simpler "shell owns foreground group = idle" rule over Ghostty's observed-prompt/agent policy, or its prototype dialog wording.

**EL-03 — Restart one pane without stale events or lost siblings.** `E:src/domain/terminal-lifecycle.ts`, `E:src/renderer/src/features/terminal/TerminalPane.tsx` (`startShell`), `E:src/renderer/src/features/workspaces/useWorkspaceController.ts` (`restartShell`), and `E:tests/terminal-lifecycle.test.ts` use attempt/session identity to ignore old exits and output while replacing a shell. GTK's `G:FEATURE_PARITY_MATRIX.md` marks Restart Shell not started; command routing in `G:swift-gtk/Sources/AwesoMuxApp/main.swift` currently has no restart route. Acceptance: restart the focused pane after its safe confirmation, retire its former surface, create a fresh surface in the same pane/layout identity, keep sibling PTYs alive, handle launch failure with a visible retry state, and ignore callbacks tagged to the previous generation. Verify repeated restart during busy output and restart immediately before pane/workspace close. Do not preserve xterm scrollback or Electron session IDs as the restart mechanism; honor the macOS restart contract.

**EL-04 — No orphaned or wrongly reattached process after interface failure.** Electron keeps node-pty in its main process while a renderer reloads: `E:src/main/index.ts` (`render-process-gone`, recoverable listing), `E:src/main/renderer-recovery.ts`, `E:src/renderer/src/features/workspaces/useWorkspaceController.ts`, and `E:tests/renderer-recovery.test.ts`. GTK's native process boundaries differ: it has profile snapshots in `G:swift-gtk/Sources/AwesoMuxCore/SessionStore.swift` and a recovery sheet in `G:swift-gtk/Sources/AwesoMuxApp/main.swift`; `amx` persistent session recovery is a separate product objective. Acceptance: after forced GTK termination, restart from a valid snapshot and attach only genuinely persistent `amx` sessions to their original workspace/pane identities; otherwise state clearly that a fresh process was started. A corrupt snapshot must not be treated as proof of a live PTY. Repeated recovery failures must stop retrying and present a recoverable state. Do not port Electron's renderer reload counter or pretend a native GTK crash preserves in-process Ghostty surfaces.

## P1: terminal content, input, and trust boundaries

**EL-05 — Concurrent output and attach ordering.** `E:src/main/terminal-replay.ts`, `E:src/domain/terminal-output-queue.ts`, `E:src/renderer/src/features/terminal/TerminalPane.tsx` (`attachSessionRef`), and `E:tests/terminal-replay.test.ts` and `E:tests/terminal-output-queue.test.ts` cover bounded UTF-8 output, snapshots, catch-up, live-event deduplication, and oversized chunks. GTK's embedded Ghostty renders directly; its `G:swift-gtk/Sources/AwesoMuxTerminalIntegration/main.swift` tests concurrent panes and Unicode, while `amx` attach/history is still incomplete per `G:FEATURE_PARITY_MATRIX.md`. Acceptance: while a persistent session emits multibyte output during attach, neither duplicate nor reorder history/live bytes; make truncation visible rather than silently implying complete history; bound memory; verify closing during attach does not resurrect a pane. Apply ordering at the `amx` history/live seam, not as a second renderer buffer for ordinary Ghostty surfaces.

**EL-06 — Pasting untrusted text remains a paste operation.** `E:src/domain/terminal-paste.ts`, `E:tests/terminal-paste.test.ts`, and `E:src/renderer/src/features/terminal/TerminalPane.tsx` show empty-paste no-op, ESC neutralization, and use of the terminal's paste path rather than keystroke replay. GTK currently routes `paste_from_clipboard` to Ghostty and tests basic clipboard round trip in `G:swift-gtk/Sources/AwesoMuxTerminalIntegration/main.swift`; `G:ghostty-shim/src/awesomux_ghostty.c` owns asynchronous clipboard reads and confirmation callbacks. Acceptance: multiline, ESC/bracketed-paste markers, huge text, invalid UTF-8 replacement, empty clipboard, and focus switch during an asynchronous read go only to the initiating pane under Ghostty's paste semantics; denial leaves input unchanged; no terminal/clipboard content enters logs. Decide the exact escape sanitization against Ghostty and macOS policy, not xterm's `paste()` behavior.

**EL-07 — Link activation checks the actual target.** `E:src/domain/terminal-link.ts`, `E:src/main/external-link-validation.ts`, `E:src/main/index.ts` (`requestExternalLink`/`resolveExternalLink`), `E:src/renderer/src/features/terminal/TerminalPane.tsx` (`linksForBufferLine`), and `E:tests/terminal-link.test.ts` cover malformed and non-web schemes, embedded credentials, punycode, bidi/invisible path characters, prefilled email, and single-use confirmation tokens. GTK's `G:swift-gtk/Sources/AwesoMuxApp/main.swift` has a general `openURL` path, while terminal link policy is not covered in the parity matrix beyond pointer/hover. Acceptance: clicking terminal output cannot launch script/custom/local-file schemes through a generic opener; confirm suspicious target with the real host/recipient and safe-default Cancel; revalidate target on confirmation; stale or duplicate confirmation cannot open. Test Unicode/wide-cell boundaries, wraps, trailing punctuation, and mismatched visible text vs OSC 8 target. Mac product rules may allow Markdown file links: derive scheme/file exceptions from its baseline rather than copying Electron's blanket local-file block. Do not port xterm's cell-index link provider or Electron IPC tokens into GTK.

**EL-08 — IME and shortcut ownership under live composition.** Electron's terminal input and app command separation are visible in `E:src/renderer/src/features/terminal/TerminalPane.tsx`, `E:src/domain/keyboard-shortcuts.ts`, and `E:tests/keyboard-shortcuts.test.ts`; the source does **not** contain a dedicated IME regression suite, so it is only a reminder to test the boundary. GTK has Unicode integration coverage but `G:FEATURE_PARITY_MATRIX.md` still marks desktop IME preedit/commit and the full key/modifier matrix pending. Acceptance: use a real Wayland and X11 IME to compose CJK text, combining marks, and emoji, cancel preedit, then switch panes mid-composition; text must enter only the owning pane once. App shortcuts remain app owned while ordinary terminal control chords reach Ghostty. Do not translate DOM composition events or copy Electron's shortcut map verbatim.

**EL-09 — Exit, failure, and search remain operable.** `E:src/domain/terminal-surface.ts`, `E:src/renderer/src/features/terminal/TerminalPane.tsx`, and `E:tests/terminal-surface.test.ts` show a visible unavailable state with cause and Restart Shell action, terminal search next/previous, Escape restoring focus, and no stale callbacks after disposal. GTK's `G:FEATURE_PARITY_MATRIX.md` marks terminal search and restart not started; `G:swift-gtk/Sources/AwesoMuxTerminal/TerminalRuntime.swift` can report `processExited` but does not expose an exit reason to the app. Acceptance: exit or launch failure presents the macOS-approved state and accessible recovery action in the correct pane; search only that pane's scrollback, handles no matches and changing output, and restores focus to that pane on Escape. Preserve sibling operation through all states. Do not copy Electron's xterm search addon or copy string.

## P2: interface consistency and remaining evidence

**EL-10 — Accessibility state and keyboard completion.** `E:src/renderer/src/features/terminal/TerminalPane.tsx`, `E:src/renderer/src/features/terminal/TerminalDeck.tsx`, and `E:src/renderer/src/features/terminal/InterruptionDialog.tsx` use labelled terminal regions, live status/alert messages, and explicit search/dialog controls. GTK already has `G:swift-gtk/Sources/AwesoMuxApp/AccessibilitySupport.swift`, named terminal surfaces, native confirmation sheets, and extensive sidebar AT-SPI work. Acceptance: with Orca, navigate two panes, hear each name and current state, encounter only the selected/visible workspace's content, operate restart/search/confirmation by keyboard, and return focus after cancellation. Verify close/race announcements once; avoid dumping terminal contents into live regions. Do not mirror ARIA roles directly to AT-SPI; validate native GTK roles and the macOS wording catalog.

**EL-11 — Focused-pane context and cheap bounded probes.** `E:src/main/index.ts` (`terminalContext`, `gitOutput`), `E:src/main/platform/linux.ts` (`terminalWorkingDirectory`), and `E:src/renderer/src/features/terminal/TerminalPane.tsx` (`refreshContext`) refresh cwd/Git only for the active terminal with bounded subprocess output and timeout. GTK has Ghostty title/cwd callbacks and focused-pane projections in `G:swift-gtk/Sources/AwesoMuxApp/main.swift` plus bounded Git helpers in `G:swift-gtk/Sources/AwesoMuxCore/FooterModels.swift`. Acceptance: two panes in different repos always show the focused one's path, branch, and changes after rapid focus switches; slow/missing Git returns a neutral state without blocking GTK; stale probe completion cannot overwrite a newer focus. Do not port Electron's `/proc/<pty-pid>/cwd` polling if Ghostty's cwd event and the product context model suffice.

**EL-12 — Visual and small-state fixtures.** `E:src/domain/workspace.ts`, `E:src/domain/settings.ts`, `E:src/renderer/src/features/workspaces/sidebar-presentation.ts`, `E:tests/workspace-state.test.ts`, `E:tests/settings-state.test.ts`, and `E:artifacts/visual-qa/matched-comparisons/README.md` retain Linux lessons about first-run, reorder/rename, keyboard selection, settings bounds, and 760×500/1220×780/1680×1000 layouts. GTK has richer grouped multi-pane state and visual QA under `G:artifacts/visual-qa/swift-gtk/`; use Electron fixtures only to spot regressions the current matrix misses. Acceptance: selected workspace and focused pane survive rename/reorder and application restore, small windows keep controls reachable, and accessibility settings visibly affect real terminal and chrome. Do not import Electron's one-terminal-per-workspace data model, simulated agent state, prototype visual styling, or feature labels as parity requirements.

## Review and prioritization rule

Work EL-01 through EL-04 before new interaction polish because they can lose or misroute live work. EL-05 through EL-09 should be integrated where Ghostty, `amx`, and GTK own the behavior; EL-10 through EL-12 are targeted QA prompts. A passing Electron unit test is evidence of an intended edge case, **not** evidence that GTK passes it. Current GTK coverage above is based on source, tests, and `FEATURE_PARITY_MATRIX.md` review; this handoff did not run the Swift app or preflight and therefore makes no new runtime parity claim. Recheck the active macOS reference and GTK status before converting any item into implementation work.
